1. TRANSACTIONAL EMAIL SYSTEM
================================================================================

A. EMAIL CLASSES CREATED
-------------------------
Location: app/Mail/

1. OrderPlaced.php
   - Sent when user places a new order
   - Implements ShouldQueue for background processing
   - Contains order details and products list

2. OrderStatusUpdated.php
   - Sent when admin updates order status
   - Shows old status vs new status
   - Includes admin remarks

B. EMAIL TEMPLATES
------------------
Location: resources/views/emails/

1. order-placed.blade.php
   - Professional HTML email design
   - Shows order number, date, total items
   - Lists all ordered products with quantities
   - Includes "View Order Details" button
   - Color-coded status badges
   - Responsive design

2. order-status-updated.blade.php
   - Shows status change (old → new)
   - Displays admin remarks
   - Color-coded status badges
   - Status-specific messages
   - "View Order Details" button

C. EMAIL FLOW
-------------

USER PLACES ORDER:
1. User submits order from wishlist
2. Order saved to database
3. OrderPlaced email queued
4. Email sent to user's email address
5. User receives confirmation email

ADMIN UPDATES STATUS:
1. Admin changes order status
2. System detects status change
3. OrderStatusUpdated email queued
4. Email sent to user
5. User receives status update notification

D. MAIL CONFIGURATION
---------------------
Location: .env

Development Mode (Current):
MAIL_MAILER=log
- Emails saved to storage/logs/laravel.log
- No actual email sent
- Perfect for testing

Production Mode:
MAIL_MAILER=smtp
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=your-email@gmail.com
MAIL_PASSWORD=your-app-password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=noreply@uoms.edu
MAIL_FROM_NAME="UOMS System"

E. QUEUE CONFIGURATION
----------------------
Emails implement ShouldQueue interface
- Emails sent in background
- Doesn't slow down user experience
- Uses database queue driver

To process queued emails:
php artisan queue:work

4. VALIDATION & ERROR HANDLING
================================================================================

A. VALIDATION RULES IMPLEMENTED
--------------------------------

Order Creation:
- quantities.* → required, integer, min:1
- Stock validation (quantity ≤ available stock)
- remarks → nullable, string, max:500

Order Status Update:
- status → required, in:pending,approved,rejected,processing,completed
- remarks → nullable, string, max:500

Product Creation:
- product_name → required, string, max:255
- product_code → required, unique
- stock_quantity → required, integer, min:0
- category_id → required, exists
- unit_id → required, exists

B. ERROR MESSAGES
-----------------
All validation errors display:
- Field-specific error messages
- Red color highlighting
- User-friendly text
- Proper positioning below fields
